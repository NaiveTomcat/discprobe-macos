# macOS 上的驱动计时标定：第一批实测数据

2026-11-04，macOS 26/27（arm64），`discprobe/macscsi.py` + `tools/mac/discprobe-spt` 后端。
一次完整的 `geo` 梯子测量，外加一次不同参考扇区的重复，得到这批 DVD-R 的螺旋几何。

## 硬件与介质

| 项 | 值 |
|---|---|
| 光驱 | MATSHITA BD-MLT UJ260AF（USB，固件 1.01） |
| 盘片 | DVD-R 120 mm，MID `RITEKF1`，2,297,888 扇区（4.38 GiB） |
| 状态 | 已封盘，profile 0x0010（DVD-ROM），disc status 2 |
| 内容 | `randburn` 写满随机数据（种子 20261104），不是本仓库写的 |

随机数据是计时法最理想的载体：`READ(12)` 每次都从介质读出，没有单一字节纹理触发的重试。
`info` 的原始输出见 `disc_info.json`。

## 后端核查（测量前先确认前提）

`python -m discprobe timing --drive disk10 --sectors 16 --reps 24`
（原始 summary：`timing_summary.json`，完整目录 `results/timing-disk10-20261104-191241/`）

- **FUA 有效。** 同一 ECC 块重复读：plain p50 **1016 µs**（缓存），`READ(12)+FUA` p50 **50665 µs**
  （真读盘）。所以 `cache.strategy = fua`，相位来自真正的介质读取。
- **CAV。** 三区（盘面 5% / 50% / 95%）周期 25.38263 / 25.38274 / 25.38196 ms，
  coherence 0.9999 / 0.9999 / 0.9922，内外比 1.0000 → **CAV**，相位法成立。
- **一圈 25.3826 ms（2363.8 rpm）**，单次相位抖动 0.65–0.87°。
  注意 50665 µs ÷ 25383 µs = **1.996**：FUA 重读固定花**两圈**，不能把 50.7 ms 当"一圈"用。
- **相位噪声。** 5 个目标单次 std 0.72–1.10°，SEM 0.15–0.23°（n = 23–24）。
- **独占访问不需要 root。** `diskutil unmountDisk` 之后 `ObtainExclusiveAccess` 直接成功。
- **常数项 c ≈ 0。** 两次拟合给出 0.011° 与 0.174°，即"解码延迟差"这个未知量确实接近零，
  这是相位确实锁在 ECC 块末端的一个独立证据。

## 主结果

`python -m discprobe geo --drive disk10 --max-targets 22 --reps 24`
（参考扇区 LBA 1011056，可读范围 3%–85%，读速 4x = 5540 kB/s）

| 量 | 值 |
|---|---|
| 级数 | 22 / 22，无一级被放弃 |
| u = r0/b | 180518.475 ± 0.015 |
| v = p/b | 5.5912078 ± 0.0000006 |
| 内半径 r0（位长 133.3 nm 时） | **24.06311 mm**（标称 24.0） |
| 轨距 p（同位长） | **0.745308 µm**（标称 0.74） |
| 拟合残差 rms | 0.206°，χ²/dof 0.887 |
| 24–58 mm 角度不确定度（1σ） | **0.174°** |
| 实测跨度 25.756–54.486 mm 的 1σ | 0.146° |
| 标称几何原本偏掉的角度 | 52218°（约 145 圈） |

也就是说：按标称几何去刻图，整盘累计会转偏 145 圈；按这组 u、v 去刻，24–58 mm 内的角度误差
约 0.17°（1σ），等效到 56 mm 处约 0.17 mm 的弧长——比设计格点 0.02 mm 粗，但只有同一处
半径误差效应的 1/5。

## 重复性（换参考扇区再测一遍）

第二遍用不同的参考扇区（LBA 689280），其余参数相同：`geo_run2/`。

| | 第一遍 | 第二遍 | 差 |
|---|---|---|---|
| u | 180518.4753 | 180518.4373 | −0.038（2.5σ） |
| v | 5.5912078 | 5.5912091 | +1.3e−6（2.1σ） |
| χ²/dof | 0.887 | 0.958 | |
| 残差 rms | 0.206° | 0.184° | |
| 1σ（24–58 mm） | 0.174° | 0.16° | |
| c | 0.011° | 0.174° | 差 0.16°，被吸收进整体转角 |

第三遍（`geo_run3/`）是把数值部分从 numpy 改写成纯标准库之后重跑的，同一张盘：
u 180518.442、v 5.5912093、χ²/dof 0.74、25.756–54.486 mm 内 1σ 0.142°，与上面两遍在运行间噪声内一致
（三遍的 u 极差 0.038，正好是单次 σ 的量级），说明改写没有改变测量结果。

两遍结果换算到角度上，在 25.8–54.5 mm 范围内相差 **+0.279°**。两次独立测量之差应是
单次 σ 的 √2 倍（0.246°），实测 0.279°，即报告的 1σ 偏乐观约 15%——和模拟里的结论一致。
**判断精度时按 0.2° 量级用，不要按 0.15° 用。**

## DiscImageStudio 预设

`dis_preset.json`（`disexport`，`--sectors 2297888`，拟合范围 25.8–54.5 mm）：

- 内半径 **24.063112765 mm**，外半径 **58.227347940 mm**（对应 2,297,888 扇区）
- 三次轨距形状系数 −2.3e−10 / −1.4e−9 / 3.5e−9（量级上就是常数轨距；这几个系数本身是"松的"，
  不同起点会落在同一条几乎平坦的谷里，判据是下面的角度差）
- 与实测角度图相比：最大偏差 **0.0010°**，rms 0.0003°

外半径是按总扇区数算的，换一张容量不同的盘要按 `fit.dis_equivalent` 里的表重取。

## 适用范围（重要）

这组数字描述的是**这张盘**的螺旋：刻录机的写速控制 + 空白盘 ATIP 共同决定。测量对象是

    (空白盘批次) × (UJ260AF 这台刻录机) × (当时那次写入的写速) × (DAO 封盘方式)

- 同一批空白盘、同一台机器、同一个写速档 → 可以直接复用，逐盘复测的意义只是确认一致性；
- 换空白批次、换刻录机、换写速 → 必须重测，差 1% 就是几千度；
- 盘上写什么数据不影响几何（只影响能不能稳定读出），所以这张随机数据盘的结果可以拿去刻图。
- **写入速度目前未知**（`randburn` 的记录里没有留），下次烧盘时记下来，这组数字才能标定清楚。

## 复现

```bash
python3 -m discprobe list
python3 -m discprobe info  --drive disk10
python3 -m discprobe geo   --drive disk10 --max-targets 22 --reps 24
python3 -m discprobe disexport \
    --geo results/geo-disk10-<时间戳>/summary.json --sectors 2297888 \
    --r-min 25.8 --r-max 54.5 --output results/geo-disk10-<时间戳>/dis_preset.json
```

整条链路只用 Python 标准库（不需要 numpy / scipy）。一次 `geo` 约 4 分钟（22 级 × 24 对），
`disexport` 约 3 秒。原始 `events.csv`（每条命令的起止时间戳）留在
`results/geo-disk10-*/` 下，体积大，没有进仓库。

## 这一批盘怎么逐张测

校准是**逐盘**的（同一批空白盘的 ATIP 相同，但刻录时各自的螺旋起止和局部写速仍会有差异），
所以剩下几张按下面的节奏来，一张盘约 5 分钟：

1. 换盘。等驱动器停稳、介质就绪（`drutil status` 有 `Type:` 行）。
2. 记下这张盘的 `info`：MID、容量、写入速度（烧盘时用的档位，这是唯一从盘上读不到的量）。
3. 跑 `geo`，把 `summary.json` 改名成 `<MID>-<序号>-summary.json` 收好。
4. 想看差异有多大，就把两次的 u、v 代进 `theta()` 比较——`evidence/mac/README.md` 里给过做法：
   换参考扇区重测一遍，两次之差应该和报告的 √2σ 同量级（这里实测 0.279° 对 0.246°）。

因为 `geo` 要独占驱动器，换盘前后不要同时开别的 discprobe 进程（`list` 会看不到驱动器）。
如果这批盘里混了 CD-R 或 DVD+R，先用 `info` 确认 profile：CD 的块长和轨道间距不同，
`geo` 的默认先验（r0 = 24 mm、轨距 0.74 µm、DVD 的 16 扇区 ECC 块）要相应改，
`--r0-mm/--pitch-um` 之外 `timing --sectors` 也要换。
